\section{What is a Lyapunov Fractal?!}
\begin{itemize}
\item characterizes orbit stability in dynamical systems
\item allows to determine ...\\ \emph{but who cares anyway, we just want pretty pictures}
\end{itemize}
\section{Pretty pictures}
Ingredients:
\begin{itemize}
\item iteration: some formula that describes a sequence of points in time
\item stability: how that sequence evolves
\item colors!
\end{itemize}
\subsection{Iteration}
Standard example: \enquote{logistic map},
\begin{align}
x_{n+1} &= r_n x_n (1-x_n), \label{eqn:logistic_map}
\end{align}
where $0\le r_n \le 4$ is a free parameter at every iteration $n$.
To keep it simple, we always start with $x_0=\frac{1}{2}$ (and all points will be between zero and one, i.e. $0\le x_n \le 1$).
\subsection{Stability}
Lyapunov's definition:
\begin{align}
\lambda &= \lim_{N\rightarrow \infty} \frac{1}{N} \sum_{n=1}^{N} \log \abs*{\frac{\d x_{n+1}}{\d x_n}} \label{eqn:lyapunov}.
\end{align}
Idea: large derivative means large change means large $\lambda$, so $\lambda > 1$ for \enquote{chaotic} orbits (but we are mostly here for the pictures).
\begin{taskbox}{What the Formula?}Using the formula of the map in \autoref{eqn:logistic_map}, compute the derivative in \autoref{eqn:lyapunov} (it is less bad than it looks, I promise).
\end{taskbox}

\subsection{Colors}
Because a constant $r_n$ is not all that exciting, we do the next best thing and alternate between two values.
For example, suppose that $r_n=2(=a)$ for even $n$ and $r_n=1(=b)$ for odd $n$ (so $r_0=a$, then $r_1=b$, then $r_2=a$ etc.; one calls this pattern $AB$).

\section{Computing the image}
A single $\lambda$ is not enough, we need more.
Keeping the $AB$ pattern for the iteration, we can create a two-dimensional grid of $\lambda$'s by running $a$ from $0$ to $4$ (and likewise $b$).

You can generate a 2d grid of $(a,b)$-values via
\begin{verbatim}
import numpy as np

a_1d = np.linspace(0,4,100)
b_1d = np.linspace(0,4,80)
a_2d, b_2d = np.meshgrid(a_1d, b_1d)

def run_iterator_2d(a, b, sequence="AB", n_iter=1024):
    results = np.zeros(a.shape, dtype=np.float64)

\subsection{Visualization}
You can create an empty \texttt{Axis} object via
\begin{verbatim}
import matplotlib.pyplot as plt

fig, axis = plt.subplots()
axis.axis("off")
\end{verbatim}
To visualize our \texttt{results} from the previous task, we can use the \texttt{imshow} function.
It displays a colored rectangle for every point in the given dataset, but it has some \enquote{quirks}: the pixel positions are offset by half the rectangle's size.
To correct for this, the following helper function is useful:
\begin{verbatim}
def get_extent(x, y):
    """Compute the correct extent for an imshow plot with 
    given (x,y)-values. MWE:
    x = np.linspace(0, 4, 9); y = np.linspace(0, 2, 5)
    x2, y2 = np.meshgrid(x,y)
    data = np.sign(y2)/(1+x2**2)*y2**2
    plt.imshow(data, extent=get_extent(x,y),
               cmap="inferno", interpolation="none")
    plt.scatter(x2, y2)
    """
    dx = x[1] - x[0]
    dy = y[1] - y[0]
    extent = [x[0] - dx/2, x[1] + dx/2,
              y[0] - dy/2, y[1] + dy/2]
    return extent
\end{verbatim}

\subsection{Colormaps}
There are plenty of default colormaps, but you can also create a custom one.
One way is to create a list of colors and have \texttt{matplotlib} linearly interpolate the RGB channels between them.
This can be done via
\begin{verbatim}
from matplotlib.colors import LinearSegmentedColormap

def get_colormap(color_list, cmap_name="custom"):
    """Convert a list of colors to a colormap.
    Format of 'color_list'-entries:
        (location, (R, G, B)) where
            -- first 'location' must be 0.0
            -- last 'location'  must be 1.0
    """
    colormap = LinearSegmentedColormap.from_list(
        cmap_name, color_list
    )
    return colormap
\end{verbatim}
Here is an example for how to create such a color list:
\begin{verbatim}
def convert_string_to_color_list(string):
    """Simple example:
    https://eltos.github.io/gradient/#0:4C71FF-100:FC4A53
    """
    segments = string.removeprefix("#").split("-")
    color_list = []
    for segment in segments:
        loc_val, hex_val = segment.split(":")
        location = float(loc_val) / 100
        rgb = plt.matplotlib.colors.hex2color("#" + hex_val)
        color_list.append((location, rgb))
    return color_list
\end{verbatim}
Because $\lambda=0$ marks a transition between qualitatively distinct regions in a Lyapunov fractal, it is useful to choose a so-called \enquote{divergent} colormap.
This means that the colormap has some pretty sudden change around the same value (often by a transition of the type color-white-color).

\section{Speed it up!}
The Python \texttt{for}-loops are pretty slow, but fortunately there is a simple fix (at least in this case):
\begin{verbatim}
import numba as nb
\end{verbatim}
The \texttt{numba} package allows JIT-compilation of sufficiently \enquote{simple} or \enquote{C-like} functions.
\emph{When} it works, it is usually as simple as adding a decorator to the function definition, e.g.
\begin{verbatim}
@nb.njit
def iterator(...)

@nb.njit
def run_iterator_2d(...)
\end{verbatim}
We can even parallelize the code using \texttt{nb.prange} instead of \texttt{range} in the outer loop and replacing the decorator by \texttt{nb.njit(parallel=True)}.
But at that point, it is probably a good idea to turn to the GPU instead...
\subsection{Power of the GPU}
If we want to interactively modify the fractal, e.g. by zooming in or changing parameters, we need to reach at least $30$ fps for a decent user experience.
That means computing the $\approx 10^3$ iterations for roughly $2000 \times 1000$ pixels in under $30\,$ms.
That's $6\cdot 10^{10}$ iterations, and in particular just as many \texttt{log} calls -- not to mention the overhead of computing the actual orbit.
Now with some SIMD-magic we can certainly do this on the CPU, but we might as well use the right tool for the job.
